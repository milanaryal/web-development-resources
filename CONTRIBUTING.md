# Contributing

Thank you for helping keep this reference accurate and useful.

## Resource criteria

- Link to the canonical project or documentation page.
- Confirm that the page is reachable and still represents the described resource.
- Prefer maintained, broadly useful resources over promotional landing pages.
- Search the README and open pull requests for duplicates and near-duplicates.
- Use a concise, factual description without unsupported marketing claims.
- Disclose in the pull request if you own, maintain, work for, or are paid by the resource.

## Formatting

Add the resource to the most specific existing section and preserve that table's
format. Use HTTPS when the canonical site supports it.

```markdown
| [Resource](https://example.com/) | One factual sentence describing it. |
```

## Pull requests

Keep each pull request focused and explain how the URL and description were
verified. Maintainers may request changes or decline submissions that are
duplicative, unmaintained, misleading, unsafe, or outside the repository's
front-end and web-development scope.

Corrections and removals are welcome. For a moved or dead resource, include the
new canonical destination or evidence supporting removal.
